## The bet (one paragraph)
FDE fits me better than any alternative: it is "build e2e + product + best pay + best skills." On raw skills I am 70-80% there already. The gap is not capability, it is legible proof that a screener believes I ship production code. So the plan is: keep Finrep as the forge (do not quit to chase a title), build public proof, target India AI startups + Forward Deployed Product Manager (FDPM) roles first, and keep global-remote frontier labs as the 24-month goal, not the next move.

- PM at Finrep (AI fintech, "Fina" agent) who ships production PRs across FE (React/TS, Mixpanel) + BE (Python), writes SQL (BigQuery/Metabase), builds agent workflows (OpenAI Agents SDK), writes LLM evals, does RCA, builds dashboards.
- Domain: financial services / SEC compliance (the #1 FDE vertical).
- Constraints: in college (start of semester), Finrep-first operating model, building capital toward the ₹1L MRR goal. So FDE prep is a slow-burn that leverages Finrep as evidence + 2 focused side projects.

## Target profile (what "FDE-ready" looks like)
A recruiter sees a builder, not a "PM intern": public GitHub leading with code, 2 shipped e2e projects, an evals case study, and an interview story that is the FDE loop (ambiguous problem → scoped with customer → shipped production code → measured with evals → fed back to product).

## Three skill gaps to close
1. **Deployment / integration in someone else's environment.** I build internal tools; FDE builds in a customer's messy env. Close it by shipping a two-system integration with real auth (OAuth/SAML), retries, rate limits, and a cloud deploy (AWS/GCP). Document the messy decisions.
2. **Evals as a headline skill.** I already write Finrep evals; make it loud. Write it up as a case study (RAG + agent evals + cost/latency tradeoffs, with numbers).
3. **Cloud + data-stack vocabulary.** Get fluent enough to talk VPC/IAM/secrets and BigQuery/dbt/Airflow in an interview. I have SQL/BigQuery; add the deployment vocabulary.

## Two portfolio projects (public, end-to-end)
- **P1 — Fintech doc-Q&A / filing-extraction agent.** Leverages my Finrep/SEC domain. Public repo + tradeoff write-up + an eval harness with real numbers. Proves: agents + evals + domain.
- **P2 — Two-system integration deployment.** Pull from one SaaS API, transform, push to another, real auth, live demo. Proves: "I ship in messy environments." This is the single most FDE-shaped artifact.
